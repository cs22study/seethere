# SeeThere 到處看看 APP — 開發內容分析與設計原理

> **版本**：Phase 0（初版技術分析與設計提案）  
> **目標平台**：Android 7.0+（`minSdk = 24`）手機／平板，以及小米電視盒子 S 2 代／3 代等 Google TV / Android TV 裝置  
> **設計核心**：無廣告、高資安、手機與電視遙控器雙模好用、可搜尋附近影像、支援自訂匯入、首頁一鍵截圖與本機日誌留存

## 1. 三方參考網站技術分析與借鏡

為確保本專案兼具高相容性、高資安防護與流暢體驗，先對三個參考來源進行結構與技術拆解：

### 1.1 `https://tw.live/cam/?id=BOT079`（即時影像監視器彙整平台）

經實測檢視網頁結構與網路請求模式，其核心運作特徵如下：

| 面向 | `tw.live` 實測現況 | 本專案借鏡與改良方向 |
| :--- | :--- | :--- |
| **影像來源結構** | `BOT079`（復興辛亥）實際來源為台北市交通管制工程處 HLS 串流（`https://jtmctrafficcctv5.gov.taipei/NVR/.../live.m3u8`），搭配 `video.js` 播放與快取縮圖 `assets.tw.live/images/taipei/BOT079.jpg`。 | **直連官方原始串流優先**，減少中介依賴；同時支援縮圖先行預覽、點選後才載入即時串流以節省頻寬。 |
| **多格式分流機制** | 針對不同政府單位自動切換處理策略：高公局 `*.freeway.gov.tw` MJPEG 採每 `7000 ms` 定時重連避免斷線；公路局 `cctv-ss*.thb.gov.tw` 與台中 `tcnvr*.taichung.gov.tw` 需走 MJPEG relay；YouTube 縮圖實作 `maxresdefault_live.jpg` → `hqdefault.jpg` 自動降級。 | 在原生 Android 端建立**統一串流路由器（Stream Router）**，依來源域名與協定自動選用對應解碼管線與重連節奏，不依賴外部 PHP relay。 |
| **附近影像查詢** | 透過 `/nearby/?ajax=1&lat=...&lon=...&radius=3000` 依據座標與半徑（預設 `3000 m`）搜尋並依距離由近到遠排序（例：`BOT322 距離約 376m`、`BOT026 距離約 454m`）。 | 將地理空間索引與 **Haversine 距離計算**內建於本機引擎，離線即可依目前座標或自訂錨點秒速排序附近鏡頭。 |
| **現存痛點（需根治）** | 網頁端嵌入大量 Google AdSense 廣告（`adsbygoogle`）與追蹤腳本（`ad-tag.min.js`、`cloudflareinsights`）；無遙控器方向鍵優化；無法個人化匯入私有/自選鏡頭；無首頁一鍵截圖與本機日誌。 | **徹底移除所有廣告與追蹤腳本**；建立手機＋TV 雙模原生介面；內建個人收藏匯入、首頁截圖與本機日誌檔。 |

### 1.2 `https://github.com/ianlkl11234s/mini-taiwan-pulse`（開源台灣即時空間資料架構）

檢視其開源原始碼（特別是 `src/data/wraDisasterCctv.ts` 與 `src/components/CctvStreamView.tsx`），歸納出三項極具價值的工程實務：

1. **動態權杖影像必須即時向官方 API 換取網址**
   - 例如水利署水情影像（data.gov.tw `36687`）的 `imageurl` 帶有每日更換的加密序號 `CCTV_SN`，若只存靜態網址隔天就會失效。
   - 必須在開啟該鏡頭時呼叫水利署開放資料 API（支援 JSON/CORS），依 `cameraid` 對應回當日有效的 `imageurl`（並加上 10 分鐘記憶體快取避免重複轟炸官方主機）。
2. **嚴格的外部資料資安過濾（防 XSS / SSRF / 髒資料）**
   - 對外部資料（如 TDX 清單常出現前置單引號 `'https://...`）先進行清洗與正規化。
   - **協定與 Host 白名單檢查**：僅放行明確許可之 `https://`（若使用者在區網測試私網 `http://` 攝影機，需經明確人工確認旗標，匯入外部清單時預設封鎖 `192.168.*`、`10.*`、`172.16-31.*` 以防 SSRF 探測內網）。
   - 阻擋 `wss://`、`javascript:`、`file://`、`data:` 等非安全協議。
   - 記錄無法在 iframe 內嵌的 `X-Frame-Options: SAMEORIGIN` 網域（如 `atis.ntpc.gov.tw`），避免黑畫面卡死。
3. **主動切斷離屏媒體資源（記憶體洩漏防護）**
   - 其 `releaseMediaIfDetached` 機制提醒我們：MJPEG 與 HLS 屬於長連線串流，切換鏡頭或關閉畫面時若未立即 `pause()` + 清除來源 + 釋放解碼器，電視盒（通常僅 2GB RAM）極易在幾次切台後發生 OOM 閃退或頻寬塞爆。

### 1.3 `https://www.youtube.com/watch?v=DjdUEyjx8GM`（YouTube 24H 即時直播串流）

1. **零成本中繼資料解析**：實測可透過官方免金鑰 oEmbed API（`https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=DjdUEyjx8GM&format=json`）直接取得影片標題（如「東京新宿歌舞伎町 24H Live」）、頻道作者與標準縮圖（`https://i.ytimg.com/vi/DjdUEyjx8GM/hqdefault.jpg`），使用者只需貼上 YouTube 連結即可自動填表新增。
2. **跨網域截圖陷阱與關鍵解法**：
   - 若 APP 僅是單純 WebView 包 HTML `<canvas>`，`canvas.drawImage` 無法擷取跨網域 YouTube `<iframe>` 的畫面（因 CORS / 同源政策限制會得到空白影像）。
   - **本專案採用 Android 原生 APK**，首頁截圖按鈕可調用系統級 `MediaProjection`，即使畫面上正在播放 YouTube Live、HLS 或任何複合介面，都能真實擷取成高畫質 PNG 存至相簿！

### 2.2 雙模裝置相容策略（手機 vs 小米電視盒子）

小米電視盒子 S 2 代 / 3 代（Google TV / Android TV）與 Android 手機有三大硬體差異，設計階段即須一併處理：

1. **Manifest 硬體特徵聲明**：
   - 必須設定 `uses-feature android:name="android.hardware.touchscreen" android:required="false"` 與 `android.hardware.location.gps" android:required="false"`，否則電視盒子在安裝 APK 時會被系統阻擋。
   - 同時宣告一般 `LAUNCHER` 與電視桌面 `LEANBACK_LAUNCHER`（附 320×180 TV Banner），讓 APP 直接出現在小米盒子首頁應用程式列。
2. **無 GPS 的「附近影像」解決方案**：
   - 手機端優先使用系統定位（`FusedLocation` / 原生 `LocationManager` GPS+網路，不強制依賴 Google Play Services）。
   - 電視盒端無 GPS 晶片時，自動改用**「預設位置錨點（Home Anchor，如住家／常看地點）」**、**縣市行政區快選**、或**搜尋地名／經緯度輸入**，一樣能在客廳電視搜尋指定地點附近 1–30 公里內的即時影像！
3. **遙控器 D-Pad 焦點與介面自適應**：
   - 偵測 `UI_MODE_TYPE_TELEVISION` 自動切換為 **TV 橫式劇院排版**：放大字體（≥ 18sp）、高對比黃/藍焦點外框（Focus Ring）、左欄分類 / 右欄影像網格；按遙控器 `OK` 放大全螢幕，頂部常駐焦點可達的「截圖」按鈕（並支援遙控器快捷鍵如選單鍵/長按或指定按鍵觸發）。

## 3. 核心演算法與計算原理

### 3.1 附近地點即時影像搜尋演算法（兩階段空間過濾）

當本機或靜態索引中存有數百至數千筆台灣／全球即時影像座標時，若每筆都直接計算反三角函數（`asin`, `sqrt`）會增加舊手機與電視盒的 CPU 負擔，因此採「邊界盒粗篩 ＋ Haversine 精算排序」兩階段法：

#### 第一階段：經緯度邊界盒粗篩（Bounding Box Pre-filter, $O(1)$ 比較）
給定查詢中心點 $(\phi_0, \lambda_0)$（單位：度）與搜尋半徑 $R_{\text{search}}$（單位：公尺，例如 `3000`），設地球平均半徑 $R_{\oplus} = 6,371,000\ \text{m}$：

$$\Delta\phi = \frac{R_{\text{search}}}{R_{\oplus}} \times \frac{180}{\pi}$$

$$\Delta\lambda = \frac{R_{\text{search}}}{R_{\oplus} \cdot \max(\cos(\phi_0 \cdot \frac{\pi}{180}),\ 10^{-6})} \times \frac{180}{\pi}$$

僅保留滿足 $|\phi_i - \phi_0| \le \Delta\phi$ 且 $|\lambda_i - \lambda_0| \le \Delta\lambda$ 的攝影機進入第二階段（極地以外可瞬間淘汰 95% 以上非目標點）。

#### 第二階段：Haversine 球面大圓距離精算
將角度轉為弧度（$\text{rad} = \text{deg} \times \frac{\pi}{180}$），令 $\Delta\phi_r = \phi_i - \phi_0$、$\Delta\lambda_r = \lambda_i - \lambda_0$：

$$a = \sin^2\!\left(\frac{\Delta\phi_r}{2}\right) + \cos(\phi_0) \cos(\phi_i) \sin^2\!\left(\frac{\Delta\lambda_r}{2}\right)$$

$$d = 2 R_{\oplus} \arcsin\!\left(\min\left(1.0,\ \sqrt{a}\right)\right)$$

篩選 $d \le R_{\text{search}}$ 之結果並依 $d$ 升冪排序，距離顯示規則為：$< 1000\ \text{m}$ 顯示 `xxx 公尺`，$\ge 1000\ \text{m}$ 顯示 `x.x 公里`。

### 3.2 多協定串流分派與防雪崩重連原理

1. **格式判定優先序（Stream Classifier）**：
   - `YOUTUBE`：匹配 `youtube.com/watch?v=`、`youtu.be/`、`youtube.com/live/`、`youtube.com/embed/`，萃取嚴格 11 碼 `[A-Za-z0-9_-]{11}` Video ID，並改寫為無追蹤 cookie 的 `https://www.youtube-nocookie.com/embed/{id}?autoplay=1&playsinline=1&rel=0`。
   - `WRA_API`：辨識水利署動態攝影機代碼（如 `wra_{cameraid}`），播放時才查快取或呼叫官方 JSON API 取得當日有效 `imageurl`。
   - `HLS`：副檔名或路徑含 `.m3u8` → 交由 **Media3 ExoPlayer** 播放（支援自適應碼率與硬體解碼）。
   - `MJPEG`：HTTP Multipart `multipart/x-mixed-replace` 或已知公路/國道 MJPEG 主機（如 `*.freeway.gov.tw`、`cctv-ss*.thb.gov.tw`）→ 由自寫 `OkHttp` 串流解析器尋找 JPEG SOI (`0xFF 0xD8`) 與 EOI (`0xFF 0xD9`) 邊界逐幀渲染至 `Bitmap`／`Canvas`。
   - `SNAPSHOT`：靜態 `.jpg` / `.png` 網址（或使用者開啟「省流量快照模式」）→ 依設定間隔（預設 `5–10 秒`）附加時間戳參數刷新並設定記憶體上限保護。

2. **指數退避重連公式（Exponential Backoff + Jitter）**：
   為避免串流暫時中斷時 APP 每秒瘋狂重連造成政府伺服器負擔或電視盒發熱，失敗第 $k$ 次（$k \ge 0$）後的重連等待時間為：

   $$T_{\text{wait}}(k) = \min\left(60{,}000\ \text{ms},\ 1{,}000\ \text{ms} \times 2^{\min(k, 6)}\right) + U(0,\ 500\ \text{ms})$$

   - 連續失敗達 $5$ 次自動轉為 `OFFLINE` 狀態並停止自動重試，於介面提供「手動重試」與「尋找附近替代鏡頭」按鈕。

### 3.3 首頁一鍵截圖雙通道原理

針對手機（Android 7+）與小米電視盒 S 2/3 代不同系統限制，設計雙通道擷取策略：

1. **快速原生通道（`PixelCopy`，無需系統權限彈窗）**：
   - 當使用者正在觀看原生播放器畫面（HLS `SurfaceView` / MJPEG / 快照視圖）並按下首頁「截圖」鈕時，可直接對視窗 `Window` 或 `SurfaceView` 呼叫 `PixelCopy.request(...)`（Android 7.0+ 支援視窗層級或 `Surface` 擷取；Android 8.0+ 支援全視窗 `PixelCopy.request(window, ...)`）。
   - **優點**：零彈窗干擾、特別適合遙控器一鍵瞬拍。
2. **完整全螢幕通道（`MediaProjection` + `VirtualDisplay` + `ImageReader`）**：
   - 當畫面包含 **YouTube 嵌入式串流**（跨網域渲染保護，一般 View/Canvas 無法擷取）或使用者勾選「包含系統狀態列截圖」時，自動啟用 `MediaProjection`（與 `EasyGo-Pedometer` 驗證通過之機制一致）。
   - 擷取 `ImageReader` 的 `Plane[0]` 後，依 `rowStride - pixelStride * width` 計算並裁切記憶體對齊邊緣（Row Padding），避免部分機型出現斜紋錯位，再存為 PNG 至相簿 `Pictures/SeeThere/`。

### 3.4 本機記錄檔（Local Rotating Logger）原理

- **寫入路徑**：寫入 App 專屬安全檔案區（`filesDir/logs/`）並支援使用者一鍵匯出至公開文件目錄 `Documents/SeeThere/logs/seethere-YYYY-MM-DD.jsonl`（Android 10+ 透過 `MediaStore.Downloads/Files` 無需額外危險權限）。
- **結構化格式（JSON Lines）**：每行一筆 JSON，包含 `ts`（ISO-8601）、`level`（INFO/WARN/ERROR）、`module`、`event`、`message`、`meta`（絕不包含密碼、Token 或私密帳號）。
- **日誌注入防護**：所有寫入字串強制去除或跳脫 `\r`、`\n` 與 ANSI 控制字元，防止外部攝影機名稱夾帶偽造日誌行（Log Forging）。
- **滾動清理策略**：單檔上限 `2 MB`、最多保留最近 `14 天` 或總計 `20 MB`，超限自動依時間刪除最舊日誌，避免撐爆電視盒有限儲存空間（通常僅 8GB/16GB）。

## 4. 資安防護架構（嚴格落實原則 2）

| 威脅面向 | 具體防禦措施 |
| :--- | :--- |
| **XSS 跨站腳本攻擊** | 1. 主介面與所有管理頁面完全原生 Compose 繪製，**零 WebView**。<br>2. 僅 YouTube 播放器使用隔離 WebView：關閉 `allowFileAccess`、`allowContentAccess`、`allowUniversalAccessFromFileURLs`，且 `shouldOverrideUrlLoading` 強制白名單鎖定（僅放行 `youtube-nocookie.com`、`youtube.com/embed`、`ytimg.com`、`googlevideo.com`），阻擋任何彈窗、跳轉外部廣告頁與 `javascript:` URI。 |
| **SSRF / 惡意 URL 匯入** | 匯入 JSON/CSV 或單筆新增時，強制經 `StreamSecuritySanitizer` 驗證：<br>- 僅允許 `https://`（若使用者明確勾選「允許本機區網攝影機」才額外核對私網 `http://` 並標示紅燈警告）。<br>- 拒絕 `javascript:`、`data:`、`file:`、`content:`、`ftp:`、`wss://`。<br>- 預設封鎖 `127.0.0.1`、`localhost`、`169.254.*`（雲端中繼資料網段）、`10.*`、`172.16-31.*`、`192.168.*`。 |
| **CSV / 欄位公式注入** | 匯出與匯入 CSV 時，針對開頭為 `=`、`+`、`−`、`@`、`\t`、`\r` 之攝影機名稱或備註自動加上防呆前綴或清洗，避免在 Excel/Google Sheets 開啟時觸發公式執行。 |
| **無廣告與零追蹤** | 不引入 AdMob、Firebase Analytics、Crashlytics 等任何第三方商業 SDK；網路請求僅限「公開串流本身」、「公開攝影機索引」與「使用者主動觸發之個人 GAS 備份」。 |
| **雲端密碼與 ID 白名單** | 若啟用 GAS 雲端同步，所有敏感管理密碼或存取口令不存於 APK 內，改由使用者輸入後送交 GAS 端進行 **SHA-256 + Salt 雜湊比對**；GAS 內以白名單常數鎖定唯一允許存取的 `SPREADSHEET_ID` 與 `DRIVE_FOLDER_ID`。 |

## 5. 可復原性與零花費架構設計（原則 3 & 原則 4）

### 5.1 軟刪除機制（Soft Delete）
- 本機 Room 資料表（`cameras`）與匯出格式皆內建：
  - `is_deleted`（Boolean，預設 `false`）
  - `deleted_at`（ISO-8601 時間戳，未刪除為 `null`）

## 6. 給專案負責人的實用意見與加值點子提案（待評估）

除了您指定的「搜尋附近影像」、「新增與匯入」、「首頁一鍵截圖」、「無廣告」、「資安」、「本機日誌」外，針對 **手機 ＋ 小米電視盒子 S 2/3 代** 的實際使用情境，提出以下 6 個實用功能供您評估是否納入開發：

1. **【強力推薦】電視牆「2×2 四宮格」＋「風景電子窗自動輪播」**
   - **情境**：在客廳小米盒子 55/65 吋電視上只看一個鏡頭太可惜！開啟「四宮格模式」可同時看 4 個路口／景點；開啟「輪播模式」可每隔 30 秒自動切換我的最愛（例如早看上班路口、晚看東京歌舞伎町＋合歡山），讓電視變成療癒電子風景窗。
2. **【強力推薦】手機「一鍵傳送至電視盒」交換碼（解決電視遙控器打字痛點）**
   - **情境**：在小米電視盒子上用遙控器輸入一長串 `.m3u8` 或貼上 JSON 非常痛苦。透過我們既有的 **GAS + Google Sheets** 零花費架構，手機上貼好網址按「傳送到電視」（經雲端密碼驗證產生 6 碼暫存碼或 QR Code），電視盒輸入 6 碼即刻完成匯入！
3. **【實用推薦】「自訂地點錨點書籤」＋「路線沿途影像搜尋」**
   - **情境**：小米盒子沒有 GPS，預存「住家」、「公司」、「宜蘭老家」、「合歡山」等錨點即可一鍵查附近影像；進階可設定「起點 → 終點」（例如台北 → 台中），自動列出沿線最近的國道/省道鏡頭，出遊前 10 秒掌握沿途天氣與車況。
4. **【實用推薦】「靜態縮圖先行／省流量模式」**
   - **情境**：手機在外使用 4G/5G 流量，或在電視盒同時瀏覽 10 支附近影像清單時，列表頁先只抓每 5–10 秒更新一次的 JPG 縮圖，點選特定鏡頭才連線播放 HLS/YouTube 串流，可大幅節省流量並降低電視盒 CPU 發熱。
5. **【實用推薦】「鏡頭斷線自動切換附近備援」**
   - **情境**：政府或民間監視器偶爾會維護或斷線。當某支鏡頭連續重連失敗標記為離線時，畫面上直接顯示「查看距離最近的替代鏡頭（例如 376m 外的下一支）」，一按即跳轉不卡關。
6. **【進階可選】「自訂定時巡檢抓圖（縮時比較）」**
   - **情境**：出遊或颱風天前，針對特定 1–2 支鏡頭設定「每 5 分鐘在本機存一張縮圖」，方便前後比對積水、起霧或車潮變化（僅存本機且限制張數上限，不佔空間）。
